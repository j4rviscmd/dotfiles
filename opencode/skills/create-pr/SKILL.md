# Pull Request 作成

## ゴール

プッシュ済みブランチから、プロジェクト慣習に沿ったPRを作成し、CI/CDが通るまでサポートする。

## ガードレール（絶対に守ること）

- デフォルトブランチ（main/master等）からはPR作成不可
- 未プッシュのコミットがある場合は先にプッシュを促す
- CI失敗時の自動修正は最大5回まで（それ以上はユーザーに確認）
- ラベルはプロジェクトの既存ラベルから選択（存在しないラベルは設定不可）
- **関連issueは自動検索で判定**（高関連なら`Closes #N`を付与、低関連なら紐付けなし）

## 実行フロー

### Step 1: 前提条件の確認

現在のブランチ、リモート設定、プッシュ状況を確認。デフォルトブランチにいる場合はエラー終了。

**完了条件**: featureブランチにいて、プッシュ済みであることを確認
**次のアクション**: 直ちに Step 2（情報収集）へ進む

### Step 2: 情報収集

以下の情報を順番に収集する（**必須項目を含む**）：

- [ ] **リポジトリ情報**: owner/repoを特定
- [ ] **言語判定**: /detect-languageを実行してPR言語を決定
- [ ] **関連Issue**: 自動検索により特定（**必須**、詳細は references/issue-search-algorithm.md を参照）
  - **スキップ条件**: 以下のブランチプレフィックスに該当する場合はissue検索をスキップ
    | プレフィックス | 理由 |
    | -------------- | ---- |
    | `release/` | バージョン管理・CHANGELOG更新が目的でissue紐付けが不要 |
  - **検索キーワードの抽出**: ブランチ名・コミットメッセージ（全件）・変更ファイル名・diffの要約からキーワードを抽出
  - **issue検索の実行**: 抽出したキーワードで `gh search issues` を実行（state=open、limit=10）
  - **候補の絞り込み**: 検索結果から上位3件を候補として選出
  - **内容確認（3件まで並行）**: `gh issue view {N} --json title,body,comments,labels` で各issueの本文とコメントを確認
  - **関連性判定**: 取得したissue本文・コメントとPRの変更内容を比較し、AIが関連性を判定
    - **高**: 候補issueの内容が変更の目的・範囲と一致 → PR本文に `Closes #N` を自動付与
    - **中**: 一部キーワードが一致するが完全一致とは言えない → 高関連の候補がなければ紐付けなし
    - **低**: どの候補も変更内容と合致しない → issue紐付けなしでPR作成
  - **結果の記録**: 判定結果（issue番号 または 「紐付けなし」）を記憶し、Step 4のPR本文生成で使用
- [ ] **PRテンプレート**: GitHub標準の場所から検索
- [ ] **ラベル候補**: プロジェクトの既存ラベル一覧を取得

**完了条件**: 上記5項目すべて取得完了
**次のアクション**: 直ちに Step 3（ラベル判定）へ進む

### Step 3: ラベルの判定

コミットメッセージのprefix（feat/fix/docs等）と変更内容から、適切なラベルを判定。プロジェクトの既存ラベルの中から選択。

例：
- `feat:` → enhancement, feature
- `fix:` → bug
- `docs:` → documentation
- `test:` → testing
- `refactor:` → refactoring

**完了条件**: 適切なラベルを1つ以上選択
**次のアクション**: 直ちに Step 4（PR内容生成）へ進む

### Step 4: PR内容の生成

- **タイトル**: コミットメッセージを参考に、Conventional Commits形式で生成
- **本文**: テンプレートがある場合は従う、ない場合は標準形式

**完了条件**: タイトルと本文の生成完了
**次のアクション**: 直ちに Step 5（PR作成）へ進む

### Step 5: PR作成とフォローアップ

- gh CLIでPR作成（ラベル含む）
- CI/CDの完了を待機
- 失敗時は原因を分析して自動修正（最大5回）

**完了条件**: PRのURLをユーザーに通知
**次のアクション**: なし（完了）

## エラー対応方針

| 状況 | 対応 |
|------|------|
| デフォルトブランチにいる | エラー終了、ブランチ作成を促す |
| 未プッシュのコミットあり | プッシュを促す |
| 関連issueが見つからない | issue紐付けなしでPR作成（自動判定） |
| 適切なラベルがない | ラベルなしでPR作成 |
| CI失敗（5回以内） | 原因を分析して自動修正 |
| CI失敗（5回超過） | ユーザーに確認 |
