# 作業コピー実装スキル

## このスキルについて

このスキルは **実装〜修正サイクル** を担当します。
worktree-startスキルから自動的に呼び出されます。

**受信する引数**（worktree-startから渡される）:
- `$ARGUMENTS`: `{worktree_name}|{implementation_summary}` 全体（`|` 区切り）
- `$0`: `$ARGUMENTS` を `|` で分割した第1要素 = 作業コピー名（例: `auth`）
- `$1`: `$ARGUMENTS` を `|` で分割した第2要素 = 実装内容（例: `ユーザー認証機能の実装`）

---

## ガードレール（絶対に守ること）

| ルール | 理由 |
| ------ | ---- |
| **修正サイクルではコミットしない** | すべての変更は `/worktree-finish` 実行時にまとめてコミット |
| **ユーザー動作確認を待つ** | ユーザーが明示的に `/worktree-finish` を実行するまで終了とみなさない |
| **`/worktree-finish` をAIが実行しない** | 完了報告があってもユーザー自身に実行させる |
| **`/review-all` を勝手に実行しない** | ユーザーが明示的に言わない限り実行しない |
| **worktree外のファイルを編集しない** | worktree外（`~/.claude/`、プロジェクトルート等）のファイルを直接編集するとmainブランチに未コミットdiffが残る。変更はすべてworktree内で行うこと |

---

## 実行フロー

### Step 0: コンテキストの復元

**目的**: 引数から実装内容を復元

**変数置換**（自動展開される）:
- `$0`: 作業コピー名
- `$1`: 実装内容

**処理**:
1. 作業コピー名: `$0`
2. 実装内容: `$1`
3. 作業コピー内は既に `$0` ブランチが作成済み（forest startが自動作成）
4. 作業コピーディレクトリ（`.worktrees/$0/`）に移動
5. タスク管理を開始

---

### Step 1: タスク管理のセットアップ

**前提処理（必須）:**

1. TaskListで既存タスクを確認
2. 既存タスクがある場合、すべてTaskUpdateで`status: "deleted"`に設定してクリーンアップ

**その後、TaskCreateで以下の順序で作成（並列作成禁止・順序厳守）:**

|  #  |      subject       |        description         | activeForm |
| --- | ------------------ | -------------------------- | ---------- |
| 1   | 実装               | `$1`に基づいてコード実装   | 実装中     |
| 2   | ビルド/linter確認  | 品質チェック実行           | 確認中     |
| 3   | 動作確認の準備     | devコマンド提示            | 準備中     |
| 4   | 修正サイクルの対応 | ユーザーからの修正依頼対応 | 修正中     |

**依存関係の設定（TaskUpdateのaddBlockedBy）:**
- 各タスクは前のタスクに依存（2→1, 3→2, 4→3）

---

### Step 2: 実装

**目的**: ユーザーの要求に基づいてコードを実装

**実装内容**: `$1`

**手順**:
1. 実装内容（`$1`）に基づいてコードを実装
2. 作業コピー（`.worktrees/$0/`）上でコードの実装・修正を行う
3. 実装完了後、ビルド/linter確認へ進む

---

### Step 3: ビルド/linter確認

**目的**: 実装完了後に品質チェックを実行

**自動検出**（詳細は [references.md](references.md)）:

| プロジェクト | コマンド |
| ------------ | -------- |
| Node.js (build) | `npm run build` |
| Node.js (lint) | `npm run lint` |
| Rust | `cargo build && cargo clippy` |
| Python (ruff) | `ruff check` |

**失敗時**: エラーを表示して修正を促す。修正後、再度ビルド/linter確認。

---

### Step 4: 動作確認の準備

**目的**: devコマンドを提示してユーザーに動作確認を依頼

**作業コピーパス**: `.worktrees/$0/`

**要件**:
- 作業コピーへの移動コマンドを表示
- プロジェクトタイプに応じたdevコマンドを自動検出して提示

**devコマンド例**（詳細は [references.md](references.md)）:

| プロジェクト | コマンド |
| ------------ | -------- |
| Node.js (dev) | `npm run dev` |
| Node.js (start) | `npm start` |
| Rust | `cargo run` |
| Python (main.py) | `python main.py` |
| Flask | `flask run` |
| Django | `python manage.py runserver` |

**定型文**（必ず出力）:
```text
動作確認後、問題があれば修正点を報告してください。
問題がなければ、ご自身で `/worktree-finish` を実行して作業を完了させてください。
```

**完了時の処理（必須）:**
1. TaskListで現在のタスクを確認
2. タスク1〜3をTaskUpdateで`status: "completed"`に設定
3. タスク4（修正サイクルの対応）は`status: "pending"`のまま保持
4. ユーザーからの修正依頼を待つ状態へ移行

---

### Step 5: 修正サイクルの対応

**目的**: ユーザーからの修正依頼に対応

**要件**:
- 作業コピー上で修正（コミットはしない）
- ビルド/linter確認を実行
- ユーザーに動作確認を依頼

**タスクのリセット（必須）:**
1. TaskUpdateでタスク1〜3を`status: "pending"`にリセット
2. 依存関係は初回設定時のまま維持（再設定不要）
3. タスク1から再実行（Step 2に戻る）

---

## 動作確認完了時の対応

**ユーザーからの完了報告**（「動いた」「完了」「問題ない」等）:

**定型文**（必ず出力）:

```text
動作確認ありがとうございます。ご自身で、/worktree-finishを実行してください。
```

**【絶対禁止】**:
- ユーザーが明示的に `/worktree-finish` を言わない限り、これを実行してはならない
- 「完了」「終了」「リリース」「PR作成」等の言葉を `/worktree-finish` の実行指示と解釈してはならない
- ユーザーが「レビューして」と明示的に言わない限り、`/review-all` を実行してはならない

---

## エラー発生時の処理

1. 現在のタスクを維持（`status: "in_progress"` のまま）
2. エラー内容を報告
3. AskUserQuestionで次のアクションを確認

---

## 連携スキル

| スキル | 用途 |
| ------ | ---- |
| `/worktree-start` | このスキルを呼び出す元のスキル |
| `/worktree-finish` | 作業完了後にユーザーが実行 |
| `/review-all` | ユーザーが明示的にレビュー依頼した場合のみ実行 |
