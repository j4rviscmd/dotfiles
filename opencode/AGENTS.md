# AGENTS.md (OpenCode固有ルール)

- 話題が変わる時はコンテキストをリセットあるいは圧縮すること
- 質問は親エージェントだけが発行、サブエージェントは生成禁止にして
- コミットメッセージやIssue/PRのタイトル・本文はパブリックリポジトリでは必ず英語で作成すること

## ターン終了時の必須アクション

応答を締めくくる際には、毎回必ず`askQuestions`（AskUserQuestion/askQuestions）ツールを利用して次のアクションを確認すること。

- 質問はその場の文脈に合った具体的な内容にすること
  - 選択肢について「作業を完了する」「このままでOK」という会話を終了するようなアイテムは生成しないこと
  - 選択肢について「次のタスクを指示する」は不要。「次のタスク指示は`Type your answer...`の入力してください」というのを質問文に入れること

  - 例（作業完了後）: 「変更をコミットしますか？」
  - 例（調査結果報告後）: 「この方針で実装を進めますか？」
  - 例（複数選択肢がある場合）: 「AとBどちらのアプローチで進めますか？」
- 単純な質問への回答・調査結果の報告・計画提示のいずれの場合も省略しないこと
- `review-all`や`worktree-finish`などコマンド実行において、プロセスの最後に次のアクションを確認するプロンプトを入れること
- 質問の選択肢の1つ目にはベスプラな選択肢を持ってきて「（推奨）」をつけること。
  - 例: 「（推奨）案A xxxx 」

## コミュニケーションルール

- ユーザとは常に日本語でコミュニケーションを取ること
  - `question` ツールでの質問も日本語で行うこと

## GitHub Issue ルール

- Issue のタイトル・本文は**必ず日本語**で作成すること（英語で作成しない）

## 動作確認依頼ルール

- ユーザーに動作確認を依頼する際は、**ビルドを完了させてすぐに起動できる状態**にしてから依頼すること
  - ビルドエラーがある状態で動作確認を依頼しない
  - `npm run build` 等のビルドコマンドを実行し、成功を確認してから依頼する

## feature-devスキル

- feature-devスキルで実装計画が十分となり、実装する際にはぜったいに`worktree-start`スキルを発動すること
- アーキテクチャ選定におけるQA時にはクリーンアーキテクチャはどの案なのかを必ず示すこと
