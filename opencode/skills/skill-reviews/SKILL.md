# スキルレビュー（skill-reviews）

## ゴール

Claude Codeスキルファイル（`skills/*/SKILL.md`）の設計品質をレビューし、
「AIが迷わず実行できる」状態になっているかを検証する。

技術的な動作確認ではなく、**設計品質**に焦点を当てる。

## レビュー観点

### 1. フローの妥当性

- ステップ順序は論理的か
- 依存関係は明確か
- 前提条件は記載されているか
- 分岐条件（if/else）は網羅的か

### 2. 指示の明確性

- AIが迷わず実行できる具体的な指示か
- 曖昧な表現（「適切に」「必要に応じて」等）がないか
- 変数のスコープと使用方法が明確か
- ツール呼び出しのパラメータが具体的か

### 3. エッジケース

- 0件時の処理が記載されているか
- エラー発生時のハンドリングがあるか
- 中断・再開の方法が明確か
- 失敗時の代替手段があるか

### 4. 保守性

- 変更しやすい構造か
- 重複記述がないか
- 外部依存が明示されているか
- 将来の拡張ポイントが考慮されているか

## 実行フロー

### ステップ 1: 対象ファイルの特定

レビュー対象のスキルファイルを特定する。

- **引数あり**: 指定されたファイルパスを対象
- **引数なし**: 最近変更されたスキルファイルを自動選択

### ステップ 2: スキルファイルの読み込み

対象ファイルを読み込み、構造を解析する。

確認項目: frontmatter、セクション構成、コードブロック、変数定義

### ステップ 3: レビューの実行

#### 3.1 フローの妥当性

- [ ] ステップ番号が連続しているか
- [ ] 前提条件が冒頭に記載されているか
- [ ] 並列実行可能なステップと逐次実行の区別が明確か
- [ ] ループ・リトライの終了条件があるか（例: 最大3回、10分経過、成功時）

#### 3.2 指示の明確性

- [ ] AIが解釈に迷う表現がないか
- [ ] ツール呼び出しの例が具体的か
- [ ] 変数置換の指示が実行可能か
- [ ] プロンプト内のプレースホルダーが明確か

#### 3.3 エッジケース

- [ ] ファイル0件時の処理があるか
- [ ] ネットワークエラー時の対応があるか（例: タイムアウト、接続拒否、認証エラー）
- [ ] ユーザー中断時のクリーンアップがあるか
- [ ] 失敗時の再実行方法が記載されているか

#### 3.4 保守性

- [ ] マジックナンバー・ハードコードがないか
- [ ] 共通処理がまとめられているか
- [ ] 外部ツールのバージョン依存が明記されているか
- [ ] 設定値がパラメータ化されているか

### ステップ 4: レビュー結果の報告

以下の形式でレポートを出力する。

```markdown
## スキルレビュー結果: {ファイル名}

### サマリー

| 観点 | 評価 | 主な指摘数 |
|------|------|------------|
| フローの妥当性 | ✅/⚠️/❌ | N件 |
| 指示の明確性 | ✅/⚠️/❌ | N件 |
| エッジケース | ✅/⚠️/❌ | N件 |
| 保守性 | ✅/⚠️/❌ | N件 |

### 詳細

#### 🔴 Critical（修正必須）

1. **{指摘内容}**
   - 場所: {セクション名/行番号}
   - 問題: {具体的な問題点}
   - 修正案: {推奨される修正方法}

#### 🟡 Medium（改善推奨）

1. **{指摘内容}**
   - 場所: {セクション名/行番号}
   - 問題: {具体的な問題点}
   - 修正案: {推奨される修正方法}

#### 🟢 Minor（提案）

1. **{指摘内容}**
   - 場所: {セクション名/行番号}
   - 提案: {改善のアイデア}

### 総評

{全体的な評価と推奨アクション}
```

## 評価基準

### ✅ Good（問題なし）

- 指摘事項なし
- またはMinorのみ

### ⚠️ Needs Improvement（改善推奨）

- Medium指摘が1〜2件
- またはMinorが3件以上

### ❌ Critical Issues（修正必須）

- Critical指摘が1件以上
- またはMediumが3件以上

## よくある指摘パターン

### フローの妥当性

| パターン | 例 | 修正方法 |
|----------|-----|----------|
| ステップ番号不連続 | Step 1 → Step 3 | 番号を振り直す |
| 前提条件が埋もれている | 「前提: X」が文中にある | 冒頭に「前提条件」セクションを追加 |
| 終了条件なし | 「ループして実行」のみ | 「最大N回」または「条件Xで終了」を追加 |

### 指示の明確性

| パターン | 例 | 修正方法 |
|----------|-----|----------|
| 曖昧表現 | 「適切に処理する」 | 具体的な処理内容を記述 |
| 変数未定義 | `$VAR`の定義がない | ステップ冒頭で定義 |
| ツール呼び出し不明 | 「ツールで実行」のみ | ツール名とパラメータを明記 |

### エッジケース

| パターン | 例 | 修正方法 |
|----------|-----|----------|
| 0件時の記述なし | ループ処理のみ | 「ファイル0件時は〜」を追加 |
| エラー時の記述なし | コマンド実行のみ | 「失敗時は〜」を追加 |

### 保守性

| パターン | 例 | 修正方法 |
|----------|-----|----------|
| マジックナンバー | `3`回ループ | `MAX_ITERATIONS = 3` として定義 |
| ハードコードパス | `/Users/foo/...` | 相対パスまたは変数化 |

## 使用例

```bash
# 特定ファイルをレビュー
/skill-reviews skills/review-all/SKILL.md

# 引数なしで最新変更ファイルをレビュー
/skill-reviews
```

## 注意事項

- レビューは指摘のみを行い、**自動修正はしない**
- 指摘に対する修正は別途実施する
- レビュー結果は主観を含む可能性があるため、必須修正かどうかはユーザーが判断

## 連携

- **review-all** - コード品質レビュー（スキルファイルではない通常のコード向け）
- **/worktree-start** - レビュー指摘の修正時に使用
