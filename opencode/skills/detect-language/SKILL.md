# プロジェクト言語判定

プロジェクトの標準言語（英語/日本語）を判定し、以下の形式で結果を返す：

```text
言語判定結果:
- 自然言語: {english/japanese}
- 判定元: {最新かつ既存5件のPR/README.md/ユーザー指定/.languageファイル}
```

## 実行手順

### 1. `.language`ファイルを確認（最優先）

カレントディレクトリに`.language`ファイルが存在する場合、内容を読み取る。

- 内容が japanese / english のいずれかとして解釈できる → その言語を採用して**終了**
- ファイルが存在しない、または解釈できない → Step 2へ進む

### 2. 既存PRを取得して判定

GitHub CLIで最新かつ既存5件のPRを取得し、タイトルの言語から最頻値を判定する。

サンプル:
```bash
gh search prs --repo {owner}/{repo} --limit 5 --sort created --json title,state
```

判定基準：
- 日本語文字（ひらがな・カタカナ・漢字）が含まれる → 日本語
- アルファベットのみ → 英語
- 60%以上が同じ言語 → その言語を採用
- 混在時は最頻値または最新PRの言語を採用

### 3. PRがない、または判定できない場合

README.mdの主要言語を確認して判定する。

### 4. それでも判定できない場合

AskUserQuestionツールでユーザーに確認する。

### 5. 判定結果を`.language`に保存

Step 2-4のいずれかで判定した場合、カレントディレクトリに`.language`ファイルを作成し、判定結果（`japanese` または `english`）を書き込む。ただし、既存の`.language`ファイルがある場合は上書きしない（ユーザーの意図的な設定を尊重）。これにより次回以降はStep 1で即座に判定される。

## 制約

- **このスキルは自然言語（英語/日本語）の判定専用**。プログラミング言語（TypeScript/Python等）の判定ではない
- 判定して結果を返すことがゴール（実装コードは書かない）
- PRタイトルのみで判定（本文は見ない）
- 5文字以下のタイトルは無視する
- `.language`ファイルはカレントディレクトリのみを探索

## 出力例

```text
言語判定結果:
- 自然言語: english
- 判定元: .languageファイル

英語を選定しました（.languageファイルに基づく）
```

```text
言語判定結果:
- 自然言語: japanese
- 判定元: 最新かつ既存5件のPR

日本語を選定しました（最新かつ既存5件のPRに基づく）
```
