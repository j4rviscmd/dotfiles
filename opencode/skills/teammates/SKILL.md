# Teammates スキル

## ガードレール（絶対に守ること）

| ルール | 理由 |
| ------ | ---- |
| **TeamCreate/TeamDeleteを使用** | 公式推奨APIでチームを管理 |
| **開始時アナウンス** | 「teammatesスキルを使用してチームを編成します。」 |
| **ベストプラクティス重視** | 感情論ではなく、業界標準やベストプラクティスを根拠に議論 |
| **アイドル通知を活用** | ハートビートは不要（Claude Codeが自動管理） |

---

## モード

### ディスカッションモード
複数の視点から議論し、ベストプラクティスに基づく結論を導出。

### 作業分担モード
タスクを分割して並列実行。

**推測ロジック:**
- 「並列」「同時に」「分担」「分割」→ 作業分担を推奨
- それ以外 → ディスカッションを推奨

---

## パラメータ

| パラメータ | 値 | 説明 |
| ---------- | - | ---- |
| 推奨チームサイズ | 3-5人 | 並列性とコストのバランス |
| タスク数/チームメイト | 5-6個 | コンテキストスイッチ最小化 |

---

## 実行フロー

### Step 0: タスク管理のセットアップ

**前提処理（必須）:**

1. TaskListで既存タスクを確認
2. 既存タスクがある場合、すべてTaskUpdateで`status: "deleted"`に設定してクリーンアップ

**その後、TaskCreateで以下の順序で作成（並列作成禁止・順序厳守）:**

| # | subject | description | activeForm |
| - | ------- | ----------- | ---------- |
| 1 | ユースケース判別 | モードの選択 | 判別中 |
| 2 | チーム編成 | TeamCreateとメンバー起動 | 編成中 |
| 3 | 作業実行 | ディスカッションまたは並列作業 | 実行中 |
| 4 | 報告と次のアクション | 結果のまとめと確認 | 報告中 |
| 5 | チーム解散 | シャットダウンとTeamDelete | 解散中 |

**依存関係の設定（TaskUpdateのaddBlockedBy）:**
- 各タスクは前のタスクに依存（2→1, 3→2, 4→3, 5→4）

---

### Step 1: 開始時アナウンス

**目的**: ユーザーにチーム編成を通知

**要件**:
- 以下のメッセージを出力

```
teammatesスキルを使用してチームを編成します。
```

---

### Step 2: ユースケース判別

**目的**: ディスカッションか作業分担かを判別

**要件**:
- ユーザーの発話内容を分析
- AskUserQuestionでモードを提示して確認

---

### Step 3: チーム編成

**目的**: TeamCreateでチームを作成し、メンバーを起動

**要件**:
- TeamCreateでチーム作成
- Agent toolでメンバー起動（team_name, nameを指定）
- TaskUpdateでタスク割当（ownerパラメータ）
- SendMessage で開始指示をbroadcast

**ディスカッションモードのロール例:**
- proponent（推進派）
- skeptic（懐疑派）
- moderator（調整役）

**作業分担モード:**
- タスクを自己完結型ユニットに分割
- 同じファイルを複数メンバーが編集しないよう注意

---

### Step 4: 作業実行

**目的**: チームメイトが作業を実行

**要件**:
- メッセージは自動配信される（ポーリング不要）
- アイドル通知が自動送信される
- 必要に応じてSendMessage で追加指示

**【重要】Claude Code公式の仕組み:**
- チームメイトは各ターン後に自動的にアイドル状態になる（正常動作）
- アイドル通知は自動的にリーダーに配信される
- ハートビートパターンは不要

---

### Step 5: 報告と次のアクション

**目的**: 結果をまとめ、ユーザーに次のアクションを確認

**要件**:
- 各メンバーの成果を整理して報告
- AskUserQuestionで次のアクションを確認
- 選択肢はディスカッション結果に基づいて動的に生成

**選択肢の設計指針:**
- 結論に基づく具体的なアクションを最初の選択肢に
- 「完了」は常に最後の選択肢に
- 3〜4個の選択肢に絞る

**アクション選択時の分岐:**
- 「実装」「コミット」など → アクション実行後にチーム解散
- 「別の議論」「追加作業」 → Step 3に戻る
- 「完了」「現状維持」 → Step 6へ

**【絶対禁止】**
- AskUserQuestionの回答を待たずにチームを解散してはいけない

---

### Step 6: チーム解散

**目的**: チームメイトをシャットダウンし、チームを削除

**前提条件:**
- Step 5で「完了」「現状維持」を選択
- または Step 5でアクション（実装・コミット等）を完了

**要件**:
- 各メンバーにSendMessage で`shutdown_request`を送信
- `shutdown_response`（approve: true）を送信
- 全メンバーのシャットダウン確認後、TeamDeleteを実行
- AskUserQuestionで次のアクションを確認

**【絶対禁止】**
- チーム解散後にセッションを終了してはいけない
- AskUserQuestionなしで処理を完了してはいけない

---

## エラー発生時の処理

1. 現在のタスクを維持（`status: "in_progress"` のまま）
2. エラー内容を報告
3. AskUserQuestionで次のアクションを確認
